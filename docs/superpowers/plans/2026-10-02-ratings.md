# Ratings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an account rate watched movies and watched episodes from 1 to 10, and see derived season and show averages on the show page and on Library and list rows.

**Architecture:** Two nullable `rating` columns on the existing per-user records (`TrackedMovie`, `WatchedEpisode`); a pure rules module for validation, averages and formatting; two actions in a new `rating-actions.ts`; reads extended inside `queries.ts` (SQL averages for many shows, TypeScript for the one show page, tied by a parity test); a client rating strip and small display pieces. Season and show ratings are never stored.

**Tech Stack:** Next.js 16 App Router (server components, server actions), Prisma 7 on SQLite/Turso, vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-ratings-design.md`

**Before writing any Next.js code, read the relevant guide in `node_modules/next/dist/docs/`** (AGENTS.md: this is not the Next.js you know). Read AGENTS.md "Rules that will bite you" as well; the ones that apply are called out per task. Never run `next dev` (it regenerates a managed block in AGENTS.md that must not be committed).

## Global Constraints

- A rating is a whole number from 1 to 10, or null (unrated/cleared). Only watched things can be rated: a movie whose `TrackedMovie.status` is `watched`, an episode with a `WatchedEpisode` row for the account. A rating action never creates a record.
- Season rating = mean of that season's rated episodes (none if none). Show rating = mean of the season ratings that exist, leaving out seasons with no rated episode, each season counting equally (none if none). Season and show ratings are never stored.
- Un-watching clears the rating: any `setMovieStatus` move to a status other than `watched` writes `rating: null` in the same update; un-marking an episode or a season deletes the `WatchedEpisode` rows (rating goes with them).
- Display: an account's own rating is a whole number ("★ 8"); averages always one decimal ("★ 7.4", "★ 8.0"; round half up on the tenths digit). Coverage text "N of M watched episodes rated" (show) / "N of M rated" (season), M = watched episodes in scope, N = those with a rating, shown only when 1 <= N < M.
- Rating is optional and never prompts. "Mark all watched" and plain "Mark watched" create unrated records.
- Every action starts with `requireOnboardedSession` above its `try`, validates every argument (non-string/odd inputs included), scopes every Prisma call by `user.id`, and calls `revalidatePath("/", "layout")` on success. Every rating read filters by `userId`; `Show` and `Episode` rows are shared between accounts, so any join to `WatchedEpisode` must carry `userId` (AGENTS.md: a relation that is a list is always truthy).
- "Finished" and "aired" are derived only in `lib/queries.ts` (AGENTS.md); do not touch them. The rating average rule exists twice by necessity (SQL for many shows, TypeScript for one show page) and a parity test must hold them together.
- Components whose state the server can change derive from props with `useOptimistic`; client-only state (open strip, error message) is `useState`; an error message is NEVER held in `useOptimistic` (it vanishes when the action settles). A server component never reads a plain value out of a `"use client"` module; `server-only` modules never reach client components.
- One additive migration (two `ALTER TABLE ... ADD COLUMN`), read the generated SQL: no table rebuilds. Generate it against a local file database only; never set `TURSO_AUTH_TOKEN` or a `libsql://` URL. The owner applies it to Turso before merge; this plan never touches production.
- Existing movie, show, Library and list behaviour and tests must keep passing.

## Review Focus

- Another account's ratings never reach your averages or rows: `Show`/`Episode` are shared, so every join to `WatchedEpisode` needs `userId`; the SQL filter must be shown to matter by removing it. (Tasks 4, 5)
- Rating an unwatched episode or a non-watched movie is refused and creates nothing; foreign ids refused. (Task 3)
- Un-watching clears: a movie leaving `watched`, an episode un-mark, a season un-mark. (Task 3)
- The SQL average and the TypeScript average agree: several seasons, a season with nothing rated, nothing rated, one rated episode. (Task 4)
- Formatting and coverage: averages one decimal, own ratings whole, coverage only when 1 <= N < M, no "NaN"/"undefined". (Tasks 2, 8, 9)
- The strip: tapping the chosen step clears, rapid taps don't corrupt, an error stays visible after the action settles and the optimistic state reverts. (Task 6)
