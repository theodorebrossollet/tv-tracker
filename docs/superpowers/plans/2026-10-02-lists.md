# Lists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an account keep private named lists of movies and shows, with an optional per-list "we've watched it" tick, behind a new Lists tab.

**Architecture:** Two new tables (`List`, `ListItem`) with real links to `Movie`/`Show`; list rules in a pure module; writes in a new `src/app/list-actions.ts`; reads in `queries.ts`; the existing search overlay gains an "adding to a list" mode; the existing show/movie pages gain an "Add to list" sheet. Library code is untouched.

**Tech Stack:** Next.js 16 App Router (server components, server actions), Prisma 7 on SQLite/Turso, vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-lists-design.md`

**Before writing any Next.js code, read the relevant guide in `node_modules/next/dist/docs/`** (AGENTS.md: this is not the Next.js you know). Read AGENTS.md "Rules that will bite you" as well; the ones that apply are called out per task. Never run `next dev` (it regenerates a managed block in AGENTS.md that must not be committed).

## Global Constraints

- List `name` is trimmed, 1–60 characters; names need not be unique. Limits: 50 lists per account, 500 items per list.
- `ListItem` has exactly one of `movieId` / `showId`; a title appears at most once per list; the same numeric TMDB id may be a movie on a list and a show on the same list.
- `trackSeparately` default false. `ListItem.watchedAt` counts only while the list's `trackSeparately` is on; switching it off keeps stored ticks, switching it on again restores them.
- Rules for "watched": personal list + movie → Library status is `watched`; personal list + show → the show is finished using the Library's derived rule in `lib/queries.ts` (never re-derived elsewhere); together list → the item has a `watchedAt`. An untracked title shows no status.
- Adding a title to a list never adds it to the Library watchlist and never changes Library tracking. Removing an item or deleting a list deletes list rows only. "Clear all my data" also deletes the account's lists.
- Adding an uncached title caches it under the existing allowances (60 new movies/hour via `cacheNewMovie`, 20 new shows/hour via `cacheNewShow`); cached titles are free.
- Order inside a list: unwatched first, newest added first; then watched, newest added first.
- Every action starts with `requireOnboardedSession` above its `try`, validates every argument, finds the list by `listId` and `userId` together, scopes every other Prisma call by user, and calls `revalidatePath("/", "layout")` on success. Every read through per-user data filters by `userId`.
- Ids are validated with `isTmdbMovieId` / `isTmdbShowId` before reaching TMDB or the database.
- Components whose state the server can change derive from props with `useOptimistic`; client-only state (open sheet, form text, an error message) is `useState`. A server component never reads a plain value out of a `"use client"` module; `server-only` modules never reach client components.
- "Show more" is a URL param bounded with `limitFrom` and named in `KNOWN_PARAMS`.
- One additive migration, applied to Turso by the owner before merge; this plan never touches production. Generate it against a local file database only; never set `TURSO_AUTH_TOKEN` or a `libsql://` URL.
- Existing movie, show and Library behaviour and tests must keep passing.

## Review Focus

- Another account's list: every action refuses `listId`s you don't own, and reads never expose them. (Tasks 3, 4, 5)
- A double-click on add races the unique constraint and must still report success; the concurrent test must really interleave. (Task 4)
- A movie and a show sharing a numeric id can both be on one list and are never confused. (Tasks 4, 5, 9)
- The 50-list and 500-item limits hold at the boundary (49/50, 499/500). (Tasks 3, 4)
- Switching `trackSeparately` off then on keeps ticks; a tick on a personal list is refused. (Tasks 4, 5)
- A title with no poster or year, an untracked title on a list, and an empty list all render without "NaN", "undefined" or stray separators. (Tasks 8, 9)
